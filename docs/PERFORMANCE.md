# Быстродействие Trace

Проверка: 10 ноября 2026, локальный Mac, Xcode 26, Debug, `CODE_SIGNING_ALLOWED=NO`. Это воспроизводимый тест отдельных операций, а не измерение FPS или запуск Instruments на пользовательском хранилище.

## Замер загрузки

`RepositoryPerformanceTests.testRepeatedLoadBenchmark` создаёт временное хранилище: 40 проектов × 20 задач, по 30 дневных статусов на проект. Всего 1 240 Markdown-файлов. Подготовка данных не включается в таймер. После одного холодного чтения выполняются три повторных; приводится медиана. Результаты сравниваются по ID, потому что исходный репозиторий не задавал стабильный порядок для одинаковых updatedAt; порядок теперь детерминирован.

| Операция | До | После |
| --- | ---: | ---: |
| Холодное чтение, мс | 388,6 | 439,9 |
| Повторное чтение, медиана, мс | 374,0 | 48,0 |
| Markdown-файлов, прочитанных при неизменённом повторном сканировании | 1 240 | 0 |

В повторных прогонах тёплое чтение занимало 44–48 мс; в таблице указан последний полный прогон. Повторное чтение ускорилось примерно в 8 раз. Холодное чтение не ускорилось: кэш добавляет работу с метаданными и памятью. Повторный проход всё ещё сканирует каталоги/метаданные для обнаружения внешних правок; абсолютное время зависит от файловой системы, железа и режима сборки.

## Изменения

- Кэш декодированных Project.md и статусов по URL/размеру/дате изменения. Событие конкретного файла принудительно инвалидирует его даже при совпадении метаданных. Добавления/удаления обнаруживаются каждый проход, неиспользуемые записи удаляются из кэша, смена vault сбрасывает кэш. Свои атомарные записи и переносы папок также инвалидируют нужные пути.
- События внешних правок объединяются с сохранением URL. Прежнее окно игнорирования всех событий после своей записи удалено, чтобы не пропускать одновременную правку в Obsidian.
- Сводка проектов и распределение задач по срокам вычисляются один раз на ревизию; распределение обновляется раз в минуту и при смене часового пояса. Идентичная загрузка/запись не переназначает массив проектов.
- Нативная таблица статусов и ограниченные выдержки вместо Markdown-дерева в каждой ячейке. Индекс проект×день готовится на фоновом executor. Полный текст и чекбоксы остаются в отдельном редакторе/списке.
- Ленивое построение длинных лент; разбор быстрого ввода один раз на body, а не при каждом обращении к computed property; подсветка не обновляет NSTextStorage при неизменных входах.
- Объединение запросов синхронизации уведомлений, игнорирование устаревшей очереди, короткий кэш успешного task-only input. Явное перепланирование принудительно сверяется с macOS. Статусы/ссылки не участвуют в ключе расписания.
- Процесс архивации выполняется на executor репозитория. Главный поток рисует интерфейс и индикатор; записи в хранилище ждут завершения архива для согласованного содержимого.

## Проверки корректности

Тесты проверяют неизменённое повторное чтение (0 файлов), изменение одного статуса (1 файл), принудительную инвалидацию внешней правки, удаление статуса, смену vault, переносы завершённых проектов, одинаковые результаты холодного/повторного чтения, инвалидацию сводок, границы календарных дней/DST, фильтры двух видов статусов и отсутствие лишних запросов к клиенту уведомлений.

Для повторения:

```bash
xcodebuild test -project ProjectTracking.xcodeproj -scheme ProjectTracking \
  -configuration Debug -destination 'platform=macOS' \
  -only-testing:PulseboardTests/RepositoryPerformanceTests CODE_SIGNING_ALLOWED=NO
```

Результат выводится строкой `TRACE_BENCH`. Тайминги не используются как жёсткий порог теста: нагрузка машины меняется. Проверки количества чтений и сохранности данных обязательны.

Итоговая проверка этой итерации: 104 теста без ошибок, включая адаптивную панель статусов шириной 440 pt. В приложении вручную проверены оба вида, поиск, период семь дней, открытие редактора из ячейки и запоминание режима при повторном переходе в раздел.
